# v0.14.0 · 让选择有依据，让费用看得见

设计日期：2026-10-25。本页区分已实现、模型假设与后续建议；不代表代码已上线，也不是针对个人的投资、医疗、法律或税务建议。

## 先拆解图片中的公式

`480 × 月开销 + K × 孩子数 + M` 有一个有用的直觉：财富目标应由想维持的生活倒推，而不是由“赚到某个整数”决定。但它不能作为家庭退休结论。

1. **480不是自然常数。** 480个月 = 40倍年支出，对应2.5%的初始年提取率。它不是年回报2.5%，也不是承诺40年不耗尽本金。退休期限、资产配置、税费、支出是否随通胀增加、市场先跌后涨都会改变结果。
2. **孩子不是几个相同的K。** 日常养育、教育阶段、地区和家庭选择不同。已在生活费中的养育不能再加一次终身K；额外教育支出可先列专项，但不能假装它在退休后永远发生。
3. **M不是可以直接估出的终身医疗常数。** 保障、报销、照护需求和支出时点需要核对。已在日常预算中的医疗、保费不要重复列入；未知项要列待核查，不填一个模型猜测的“正确数字”。
4. **净资产不等于可提款资产。** 自住房、车辆、锁定退休账户和应付负债不能直接按现金使用；若打算出售住房或还贷，需要把变现成本、税和未来居住支出同时调整。
5. **在职收入不该抵扣退休生活费。** 仅从退休起可获得的税后可靠收入才能在这个简化模型中抵扣。65岁才开始的养老金不能拿来填50–64岁的桥接缺口。
6. **今天的钱与未来的钱必须统一。** 未来名义金额不应直接和今天的支出比较；投资回报与月投入也必须使用同一购买力口径。

Morningstar的研究把提取率与固定年限、组合、通胀调整和成功率联系在一起，而非给所有家庭一个万能数字。[2026提取率研究说明](https://www.morningstar.com/retirement/whats-safe-retirement-withdrawal-rate-2026)、[较长退休期限研究](https://www.morningstar.com/retirement/how-much-can-you-safely-withdraw-if-you-retire-early)。不能把研究中的某一提取率当成加拿大家庭的税后保证。加拿大的退休安排还应核对养老金、收入来源与目标生活：[FCAC退休规划](https://www.canada.ca/en/financial-consumer-agency/services/retirement-planning.html)。

## 已落地的改良版

全部先用今日CAD购买力：

```
税后年缺口 = max(0，12 × (月生活费 + 尚未计入的额外月支出) − 退休起可得税后年收入)
税前提款需要 = 税后年缺口 ÷ (1 − 提款有效税负假设)
生活费本金 = 税前提款需要 ÷ 初始年提取率
总目标 = 生活费本金 + 缓冲金 + 未重复的一次性专项
```

提款有效税负是用户场景参数，不是加拿大税制引擎。默认0明确不等于免税；混合TFSA/RRSP/非注册账户不能凭一个比例完成真实税务规划。2.5%的初始值仅便于对应原图，不标为推荐或“更安全”。

入口：财富工作台 → 增长行动 → 财务自由；也可打开 `/#financial-freedom`，全站搜索支持“FIRE／退休／提取率／480”。没有再建一个孤立大页面。

### 增长路径的计算口径

- 税费后名义回报不继承资产表“本年回报”；后者不是未来预测。
- 实际年回报 = `(1 + 名义净回报) / (1 + 通胀) − 1`，再换算月回报；月末投入。
- 月投入以今日CAD表示，假设未来随通胀调整。可核对计划投入是否超过已录入预算结余；预算结余仍不等于已发生储蓄。
- 所选资金先分给缓冲与专项，剩余才参与增长；后续月投入先补足隔离资金。隔离资金假设保值至目标日，不同时获得投资回报。不是承诺现金无通胀损失。
- `少花500`是长期、可持续减支的敏感性，不是要求削减必要开支；`先跌20%`只冲击增长本金，不是最大回撤或损失概率。
- 不模拟逐年教育提款、退休后市场路径、年金领取年龄、分账户税负、房贷摊销、汇率、保险精算或Monte Carlo成功率。结果是讨论起点，不是完整退休计划。

### 对财富增长真正有用的insights

**把“提高收益率”降为一个杠杆，而不是唯一答案。** 不断提高回报假设可以让图更漂亮，却未必可实现；提高可持续留存、控制长期费用、延后提款和缩小真实生活缺口才是可以讨论和验证的行动。

**把总财富、可支用资本、风险承受能力分开。** 房产占比高的家庭可能净值充足、流动性不足；把本金门槛和资金来源并列，比一个净资产进度条更实用。

**把计划与真实执行分开。** 情景从预算和资产读取事实，计划本身不增加资产；用现有贡献记录和季度复盘核对“留存是否实际发生、支出是否漏记、假设是否还成立”。季度入口已联动，但尚未新增自动采集的季度FIRE历史序列。

**把健康／教育的不确定性变成待核查清单。** 先查保障、时间和已有预算，再讨论资金，而不是让多个LLM投票生成一个费用常数。用户可显式把摘要交给顾问，要求先审假设与证据缺口。

**让AI费用也可复盘。** 模型多、回答长、费用高不等于决策质量高。先让两位轻量模型独立找分歧，再只针对未解决的问题增加旗舰或裁判，比每场全员全流程更有成本意识。本次没有偷偷改变用户已选模型或流程。

## 研讨成本如何核算

入口 `/council`，每场显示成本卡，支持整场含全部追问或当前轮次、按模型／环节分布、逐次用量和官方计价依据；Markdown导出附费用摘要。

- 用服务商返回的tokens，不按中文字数猜测。输入、缓存命中、5分钟／1小时缓存写入、输出和推理细分分开保存；推理通常已含在输出，不能再次加算。Gemini候选与思考用量按其返回口径合计。
- 新调用保存精确API型号、直连／百炼渠道、地域与版本化公开单价；回看不重新定价。原生Anthropic、OpenAI Responses与兼容接口分别归一化。
- 原始研讨、追问、裁判都统计；自定义重复环节按稳定phase_id区分。失败但收到用量、只有推理无正文、截断回答都不能当作免费；请求尚未发出才不计。网络未知不自动重发。
- 公开搜索有自己的LLM用量及实际`web_search_call`费用。其模型tokens和搜索费均进入总额与分布；回执复用不重复计。只知道搜索费却未知模型价格时，显示已知小计加未知；本地数字运算／文字检索不另收API费。
- 已核价的具体型号使用来源标注的USD/百万tokens。DeepSeek峰谷价格和未知缓存命中显示区间，不猜计费发生时刻。缓存写入期限不明不捏造精确金额。
- **百炼价格不是原厂价格。** 仅已核实新加坡精确SKU才估算；`ZHIPU/GLM-5.3`未核实该渠道确切价格，保持未知，不套用`glm-5.3`或GLM原厂价。未核实的自定义型号、直连Kimi/Meta也保持未知。
- 旧记录有用量却没有价格快照，只能按当前已核实价格作参考重估；缺用量不能补造历史账单。新记录显式标记未知价格后，也不会在未来静默补价。
- 费用分布以已知估算上界比较，不能理解为精确供应商账单占比。未含税、套餐、赠送额度、账户折扣和订阅费用；不自动换算CAD或写入家庭支出。

价格核对日期：2026-10-25。来源：[OpenAI](https://developers.openai.com/api/docs/pricing)、[Anthropic](https://platform.claude.com/docs/en/about-claude/pricing)、[DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/)、[百炼](https://www.alibabacloud.com/help/en/model-studio/model-pricing)、[GLM原厂](https://docs.z.ai/guides/overview/pricing)、[Gemini](https://ai.google.dev/gemini-api/docs/pricing)。公开价是估算依据，不等于账户账单。

## 持久化、权限与测试范围

- 共享规划保存在既有家庭文档 `plan.values.financial_freedom_v1`（版本化JSON字符串），包含在备份与原同步流程；与资产、预算、目标共用财务指纹，脏草稿遇新数据不覆盖。用户须显式保存，未保存草稿刷新可能丢失。
- 成本快照保存在本人研讨步骤`usage.price`，搜索计费在工具回执`billing`；沿用现有私密研讨RPC与RLS。成本不是新账本，研讨也不会自动附带财富数据。
- 顾问上下文只读取已保存假设与确定性结果；本地降级助手可解释财务自由。用户主动送审草稿时明确标注草稿，不自动保存或调用外部服务。
- 不需要新的SQL、数据库凭证、定时任务或依赖；不改公开注册和数据访问边界。
- 单元／组件验证覆盖计算、缓存／推理与失败计费、历史估算、搜索去重、导出、假设校验、冲突和保存。界面预览使用隔离合成数据，不连接真实家庭账户或付费模型。最终执行结果见仓库`TEST_REPORT.md`，不把旧版浏览器数量算入本轮。
