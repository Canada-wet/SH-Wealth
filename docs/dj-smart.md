# 智能编排与本机音频 Cue（v0.5.0）

入口：`/lifestyle#library` 每首曲目后的「智能 Cue」；`/lifestyle#sets` 的「一键智能编排」。不安装本机助手，不读取 rekordbox 数据库；沿用私密家庭同步与 XML 交换。

## 一键编排

选择目标时长、起始曲（或自动）、风格、能量曲线（升温 / 稳定 / 起伏后收束 / 降温）、已知 BPM 最大估算变速、重叠计划。基于现有四项加权排序，再按全场目标能量调整；每步显示匹配理由与资料覆盖率。明确确认后保存为新的 Set，不覆盖旧编排。

- 未知字段保持未知、中性排序并提示。时长未知或不足 10 秒不参与目标时长规划。
- 可优先使用已保存且名称含混入 / Intro / Mix In、混出 / Outro / Mix Out 的非 Loop Cue；包括用户确认的音频候选，仍需试听。
- 每首至多一次，一次最多 100 首。没有合适候选就停止、展示时长差额，不重复或硬切末曲凑数。不是全局最优求解器。
- 变速比较相邻原速，保调 / 半双拍沿用现有推荐设置，不是整场 BPM 曲线；时长未按变速缩放。
- 重叠按 BPM 与 4/4 假设估算，受前后片段长度保守限制，不是检测到的乐句 / 自动对拍。实际连播需校拍、试听。
- 预览后兴趣数据改变须重新生成，保存有指纹与云端版本冲突保护，不改财富或财务历史。
- 新 Set 与 Cue 追加均先检查兴趣数据 3MB 边界，不生成无法按当前兴趣备份恢复的大文档。

## 本机 Cue 流程

选择有权使用的本地音频，每次一首，1 秒–12 分钟、最大 64MB；格式与 DRM 支持由浏览器决定，手机大文件建议转到电脑。先检查时长，再用 OfflineAudioContext 解码至 11,025Hz；跨声道功率避免反相音频被抵消为静音。PCM 转给 Worker，在本机计算 100ms 能量包络、前后各 4 秒变化和开始 / 结束参考。

候选是启发式建议，不是频谱 / 人声分离 / 曲式识别，不宣称找到真实 Drop、Breakdown 或副歌。仅有真实来源 4/4 BeatGrid、有效拍速及足够连续区间时才建议 4 小节 Loop，不跨拍速段，不保证无缝或无人声。

每点可试听、改名、调毫秒位置 / Loop 结束或取消。必须确认正确音频版本和试听核对，才可追加。实测与已有时长差异超过 max(2 秒, 1%) 停止，不根据文件名猜测关联。未知时长可选择填入整数实测秒；不覆盖既有时长、BPM、调性、能量。

默认新增 Memory；可依序填入空闲 Hot A–H。同位置 / 类型去重，64 标记容量或空槽不足则停止，不覆盖原 Cue。保存名称仍标「音频候选」，便于辨认来源。XML 可带回全局 Cue / Loop 与 Set 曲序；Set 片段 / 重叠 / 转场不等于全局 Cue。缺文件路径仍须补齐，浏览器 File 不能推断原电脑完整路径。

## 隐私与资源

- 不上传音频、不调用模型，不把文件、PCM、包络、候选原因或 blob URL 写入家庭 JSON、云端、备份或顾问上下文。只保存用户确认的 Cue 名称、时间、类型 / 槽位和可选空白时长，双方可见。
- 音频不持久保存；刷新后试听需重新选文件。分析线程代码是应用静态资源，首次需加载，不等于首次打开完全离线。
- 元数据与 Worker 可取消，关闭页面丢弃旧结果、回收 blob URL、停止播放器 / Worker。原生 decodeAudioData 无取消 API；取消后等解码结束再释放全局锁，避免重复堆积解码。
- 测试用合成正弦 / 静音 / 能量变化文件，不读取用户歌曲；不代表真人听感、全部编码、所有 Safari 真机、原生 rekordbox 或硬件认证。

参考：[解码与重采样](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData)、[离线音频上下文](https://developer.mozilla.org/en-US/docs/Web/API/OfflineAudioContext)、[Worker 数据传递](https://developer.mozilla.org/en-US/docs/Web/API/Worker/postMessage)。
