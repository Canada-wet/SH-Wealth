# Funda 开盘 / 收盘私密研究任务

The user explicitly confirmed that Funda's authorized representatives consented to two daily automated market queries and storing the answers in this household app. Do not upload or revisit the acquisition agreement. Authorization is scoped to the existing account, public market prompts, private storage and this frequency; no public redistribution, model training, trades, account/permission changes, hidden endpoints, cookie extraction or bypassing login, CAPTCHA, quotas or payment controls.

Two local Codex heartbeat tasks resume this chat. Opening runs at 09:40 America/Toronto on weekdays. Closing checks at 13:15 and 16:15; the helper is due only at 13:15 on an official half-day and at 16:15 on a normal day. At the other check, stop quietly without contacting Funda. Full holidays / weekends are skipped. Fixed NYSE calendars cover 2026–2028, with explicit failure for other years; check official NYSE notices for exceptional closure before submitting. Never claim an unexpected closure was a normal session.

The Mac must be awake, online, with Codex running, Chrome connected and Funda signed in. This is not a Vercel browser job. Local configuration at `.local/funda/config.json` contains target identifiers and the path of an already installed official Supabase CLI, never browser credentials. `.local` is excluded from Git and deployments. The existing Supabase management login must remain valid; if unavailable, stop and ask the user to restore it, do not extract or print keys.

## Each run (phase is `open` or `close`)

1. Work in the repository. Run `node lib/funda-runner.cjs due PHASE`. Stop quietly if `due` is false; do not catch up at a different time. Check official exchange notices if the session might be unexpectedly closed.
2. Run `node lib/funda-runner.cjs check PHASE`. A non-null `report_id` means this session is already archived: do not query again. A pending row with a `source_url` means resume that visible conversation, never submit a second question. A pending row without a URL is uncertain: stop, report the blocker and ask for review. Never delete, expire or automatically reclaim an uncertain run.
3. For a new slot only, obtain the exact prompt with `node lib/funda-runner.cjs prompt PHASE`, then run `node lib/funda-runner.cjs claim PHASE`. Continue only when its rows contain `claimed: true`. Retain the returned run token; it is a fencing identifier, not a platform credential. Atomic uniqueness is household + Toronto day + phase.
4. Use the supported Computer Use browser interface and the user's connected Chrome profile with Funda. Follow current browser tool instructions and inspect visible UI. Open a fresh Research Chat at the observed https://funda.ai/agent-chat interface, not the existing holdings project. Submit only the helper's public-market prompt, once. Do not send household holdings, amounts, names, files or chat history. Do not choose Deep Research, buy credits or upgrade a plan. If the profile is ambiguous, login expires or UI blocks access, stop and ask.
5. After submission, record the visible conversation URL immediately with `node lib/funda-runner.cjs attach PHASE TOKEN URL`. If a database write fails, retain the URL and do not re-submit. Wait in bounded intervals with progress only when relevant. After about ten minutes without a completed answer, leave the conversation recoverable and report pending status; do not regenerate automatically.
6. Once the answer has visibly finished, use the visible **Copy message** button and read that clipboard result. Preserve the exact raw answer, including its own caveats and original dates. Export a fresh JSON artifact into `.local/funda/` (private mode 0600) with only `source: "funda"`, visible `source_url`, current ISO `captured_at`, exact helper `prompt`, raw `response`, `citations: [{title,url}]`, `status: "complete"` (or `"partial"` for a visibly ended incomplete result), and `verification: "ai-unverified"`. Extract citation links from the visible copied answer / DOM only; never invent references. Funda's copy may use `<reference url="...">title</reference>` tags. Do not reuse `/tmp` files or the earlier single-test answer. Do not send the answer to another AI provider.
7. Run `node lib/funda-runner.cjs finish PHASE TOKEN ABSOLUTE_JSON_PATH`. The helper checks freshness, exact session prompt, target project and membership, fencing token, source URL, duplicate completion and exact readback; the archive + run completion are one database transaction. Only `archived: true` and `exact_readback: true` mean success. On ambiguous failure, retry this exact finish operation with the same token and file, never re-query Funda. Do not touch household_documents, assets, snapshots, chat, budgets, goals or release/deployment state during scheduled runs.
8. Confirm the saved record is available in https://sh-wealth.vercel.app/markets#research-archive using the already authorized app session when available; never change household or log into an unrelated profile. Keep financial data out of screenshots. Preserve a result screenshot in private local artifacts if UI was changed. Treat the source's “verified” labels as claims, not app verification; do not put AI-derived numeric values into official market curves.

Remain quiet for skipped, unchanged or already-completed slots. Notify on a meaningful new archived report with its app link, or a failure / uncertain submission / required user action. Do not keep sending unchanged blockers. If the user revokes authorization or pauses the task, stop future collection. Changing the schedule, recipients, purpose or permission scope requires user direction.

## Deployment boundaries

`supabase/research-runs.sql` is additive and requires the original archive/access schema. `lib/funda-runner.cjs` uses only built-in Node modules and invokes the installed official CLI under the existing management login, restricted by its fixed SQL operations. It never controls a browser itself. Scheduled agents must use Computer Use, not shell-based browser control. The raw reports, local configuration and acquisition agreement are never committed or deployed.
