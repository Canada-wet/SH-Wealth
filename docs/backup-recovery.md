# 可见资料导出与隔离恢复演练

本轮增加的是**本人可见资料的有界跨表导出**与本地迁移文件校验，不是全数据库备份、全量历史保证或通用一键恢复。导出不会修改数据库、消耗模型额度、重新发送消息或重新执行研讨/Funda。

## 导出契约

登录后，在数据设置明确确认导出。客户端发送同源 `POST /api/backup`：

```json
{ "householdId": "已加入家庭的 UUID", "confirm": true }
```

接口先验证白名单账号与家庭成员关系；只使用该账号的 Supabase 客户端、RLS 和安全只读 `list_wealth_actions` RPC，不用 `service_role` 绕过隔离。它不接受客户端 user ID、表名、任意查询或收件人。GET 不导出。返回 `private, no-store` 的 JSON 附件，下载名没有邮箱或家庭姓名。

文件包含 `kind=together-user-visible-export`、`schemaVersion=1`、`exportedAt`、读取开始时间、`scope`、`sections`、`counts`、`limits`、`excluded` 和 `restorePlan`。`status=complete` 仅表示本次选定字段/可见记录没有发现遗漏；它不表示完整数据库、所有家庭、原件备份或事务一致性快照。读取时如果有同步写入，数量变化会标为 partial；相同数量的替换未必可检测，不保证跨表时间点一致。

| 部分              | 数据范围                                               | 默认记录上限 / JSON 字节预算 |
| ----------------- | ------------------------------------------------------ | ---------------------------- |
| `household`       | 当前家庭主文档，包括共享聊天、计划、兴趣元数据         | 1 / 1,200,000                |
| `cloudHistory`    | 同家庭云端文档修订，最近在前；不同于主文档中的财务快照 | 30 / 600,000                 |
| `navigation`      | 本人的导航与置顶                                       | 100 / 30,000                 |
| `learning`        | 本人在当前家庭的收藏与学习订阅偏好                     | 1 / 30,000                   |
| `council`         | 本人研讨、追问、已保存附件表示与工具回执               | 30 / 1,000,000               |
| `councilLibrary`  | 本人研讨标题、标签、置顶、归档、笔记与复核日期         | 100 / 160,000                |
| `researchArchive` | 当前家庭 Funda 研究原文与来源，最近在前                | 90 / 500,000                 |
| `researchRuns`    | 同家庭研究运行状态；不含 fencing token                 | 180 / 80,000                 |
| `actions`         | 安全 RPC 返回的家庭共享行动与本人私有行动              | 100 / 120,000                |

总文件硬上限为 3,800,000 UTF-8 字节，为部署环境的响应限制留空间。各表稳定排序并有界分页；行动 RPC 一次返回可见集合，随后在内存按同样预算分页。过大的单条文档、研讨或附件**不拆坏、不静默截取**：该行及其后的记录不包含，section 给出 `byte_limit`、`truncated=true` 与第一个未导出偏移。页数/条数到上限、读取失败、缺表、异常格式、范围不符及超时也逐段报告；已成功读取的其他部分仍可保存。`continuation` 是诊断位置，不是当前版本支持的续传参数；没有假装后续资料已导出。

某个模块尚未安装会造成 partial，不能把空数组当成“确定没有记录”。主文档缺失也会明确报错。请检查每段 `status`、`issues`、`count`、`totalAvailable`；总数只代表该段读取当时，可能为未知值。附件未能装入预算时，仍需回到私密研讨逐场保存/导出；原始音频、原始 PDF/DOCX 及未保存草稿不在本包。

## 归属、保密与排除

- 家庭主文档、云端修订与研究归档是共享资料；家庭成员姓名和财务明细也会包含。本人研讨、导航与学习偏好保持本人范围。行动中的伴侣私有项不可见，伴侣共享项的 `sourceRef` 由安全 RPC 按原作者权限处理。
- 本轮不查询任何通知渠道/目的地/地址密文/哈希、连接码、Push endpoint、订阅对象、Auth 用户表、会话、密码、部署环境或平台密钥。已知 JSON 内部 claim/token 等运行凭据也会移除，`redactedFields` 明示移除数量。用户自己写进笔记/聊天的敏感文本不会被当成平台凭据自动识别；请保护整个文件，勿公开上传。
- 未包含学习/渠道投递日志、调用配额、公开市场日报、旧版规范化表、数据库角色/权限/函数定义、平台级备份或迁移执行历史。操作状态不适合复制到新项目后继续执行；不可从包里恢复未确认付费调用或重新发送通知。
- 不加密的 JSON 是敏感明文；`no-store` 只是 HTTP 缓存策略，不是文件加密。下载到可信设备，以加密介质保管；退出 App 不会删除导出文件。

## 原有财富 JSON 路径继续保留

数据设置中的“导出完整备份 / 导入备份”仍处理 **WealthState v3 主文档**，不是本跨表 bundle。不要把本包直接交给旧导入器。只有在人工检查、通过 `validateState` 且确认修订/共享影响后，才考虑提取 `sections.household.data[0].document` 走既有预览/确认流程。`document=null`、section partial/error 或缺失不能冒充可恢复主文档。

本包不包括本机未同步更改。发生云端冲突时，应先分别保留旧 JSON 本机备份与本包，再明确比较，不能用“导出云端”覆盖本机唯一副本。

## 迁移文件清单，不是自动迁移器

`supabase/migrations/manifest.json` 固定列出现有 SQL 的路径、SHA-256、顺序和依赖。执行：

```sh
node scripts/check-migrations.cjs
node scripts/check-migrations.cjs --json
```

它只读取仓库本地文件，检查缺失/未列出 SQL、重复 ID、路径越界、依赖顺序与 checksum；不加载 `.env`、不连接 Supabase、不执行 SQL、不创建远端迁移历史。修改 SQL 后应先审阅实际变更、兼容性和回滚/恢复办法，再更新清单 hash；不能靠重写 hash 宣称已部署。

**已有数据库必须人工 baseline**：核对其真实表、函数、RLS 与此前发布的实际执行记录，建立明确的已应用版本映射。`schema.sql` 是早期非幂等 bootstrap，已有库不能为了“补齐清单”重跑；当前 manifest 不是远端执行日志。后续应采用新的不可变、版本化增量文件，不把旧 checksum 变化等同安全升级。新空库也需先检查依赖、Auth 策略及测试账号；清单通过不表示 SQL 一定正确或项目可以公开使用。

## 仅在隔离项目开展恢复演练

本轮未实现通用 restore API。以下是人工演练计划，**不应对生产执行**：

1. 新建明确隔离的测试项目，记录其项目 ID，并核对它不是生产。先禁用所有 Cron/渠道发送/Funda 唤醒和付费模型，测试密钥不能复用生产密钥；不得将演练接入真实收件地址。
2. 核验 manifest 与计划安装的 SQL。对空项目人工按依赖安装；创建受控测试身份和新家庭，再明确记录旧/新 UUID 映射。Auth 密码、登录态、白名单与角色不从导出包恢复。
3. 离线检查包的 `scope`、各段状态、截断和选定字段（v0.12.0 起新增第九段 `councilLibrary`）。优先核验可用 v3 主文档的资产、负债、现金流、贡献、财务快照、聊天和兴趣数量；主文档内财务 history 与云端历史不要重复当成同一种事件。整理记录可能关联到本包因条数/容量限制未导出的研讨，恢复时必须先核验外键，不自动创建缺失原文。
4. 在隔离环境，用现有财富 JSON 导入预览已核验的主文档；其他独立表仅按逐表人工恢复计划处理，先映射家庭/用户/外键，再验证 RLS 和唯一约束。原始文件、操作 claim/token 与通知连接不恢复；不要把 active Council/Funda 状态当作可自动继续的任务。
5. 使用两位合成测试成员验证共享内容与本人私有内容的隔离，核对行数、附件可读性、金额与财务日期。包中缺失或截断部分记录为无法证明恢复，不能宣称完整恢复。记录演练结果、差异、耗时和可重复步骤。
6. 演练通过只证明该隔离样本的指定恢复路径。生产回切、完整灾难恢复、停写窗口和跨表一致性仍需单独设计、授权及审查；本次没有执行这些操作。

纯测试使用合成数据与临时 SQL 文件；不需要真实家庭数据、生产环境变量或任何付费 API。
