# 兴趣与生活 · DJ Set Assistant

独立 `/lifestyle` 页面，在家庭首页、市场、学习等页面的左侧导航 / 手机导航均可进入。沿用现有私密登录和家庭空间，不改成新的公开网站。

第一版采用「一个较深的爱好 + 一个轻量仪式」：DJ 曲库 / Set Builder，以及没有连续打卡压力的练习与快乐记录。没有自动添加示例曲库，数量来自实际保存记录。

v0.5.0 加入[一键编排与本机音频 Cue](dj-smart.md)：不安装助手、音频不上传；逐点试听确认后保存候选，并与新 Set 和 XML 导出联动。

## 曲库

- 手动增删改曲名、艺人、BPM、调性、风格、能量 1–10、时长、Cue 备注、个人评分 1–5；未知可留空，不当成零。
- 调性接受 Camelot 1A–12B 以及 Am、C major、F# minor 等常见写法，规范保存为 Camelot；本机音频分析仅提出能量变化 / Cue 候选，不推断未知调性或 BPM。
- 每首最多 64 个命名 Cue 时间点，支持 Memory / Hot Cue A–H、Loop 结束与小数秒。Cue 不遥控播放器，可通过 [rekordbox XML 交换](rekordbox.md) 带入实际 DJ 软件。
- 搜索、风格过滤、排序；桌面表格和手机卡片使用同一份数据。
- CSV 在浏览器本地解析，先预览，明确重复 / 忽略列，再确认提交；任何一行不合法则整批不写入。支持带引号逗号、多行备注、BOM、中文列名与下载模板。
- 删除前确认，显示关联影响并支持安全撤销；已有新修改时拒绝撤销覆盖。

CSV 默认字段：`title,artist,bpm,key,genre,energy,duration,rating,cue_notes,cues,file_location`。`duration` 用 `分:秒`；`duration_seconds` 用秒，二者不要同时提供；`cues` 可用合法 JSON 数组 `{id,label,seconds,type?,num?,end?,color?}`。有路径时按规范文件 URI 去重，无路径时按曲名 / 艺人 / BPM / 调性，不以重复行覆盖旧曲目。CSV 不携带完整来源 BeatGrid / 扩展资料，请用 XML 交换或 JSON 备份。

CSV 导出对公式开头的文本加前导单引号，避免表格执行公式；这类文本再导入可能保留该单引号。需要完全无损恢复时用 JSON 兴趣备份。

## Set Builder

新建 Set，选择所属成员或共同、目标分钟，手动选择起始曲，再从候选中选择下一首。支持顺序调整、移除、转场备注、每首 Cue In / Out、混入重叠秒数，以及导出文本计划。

推荐是可调整的启发式，不调用 LLM，不消耗模型额度：

`Score = 100 × (wB × B + wK × K + wE × E + wP × P) / Σw`

默认权重 30 / 30 / 25 / 15；每项权重 0–100，总和必须大于零。

| 分项 | 规则 |
| --- | --- |
| BPM | 用下一首匹配当前 BPM 所需的相对变速比例；12% 或更大偏移得 0，完全匹配得 1，线性插值 |
| 调性 | 同调 1；相对大小调、同环相邻调 0.9（含 12↔1）；其余基础路径外 0.15，需试听 |
| 能量 | 目标是当前能量加用户所选变化量 -2…+2，限制 1–10；距目标相差 4 或以上得 0 |
| 偏好 | 65% 个人评分归一值 + 35% 已选风格匹配；未选择风格为中性 |

未知分项取 0.5 中性，不表示兼容。每个候选同时展示数值、理由和按权重计算的资料覆盖率；覆盖率不是成功概率。默认假设设备启用 Key Lock，用户可以关闭；关闭后有变速时不使用原始调性冒充变速后的调性。半拍 / 双拍比对默认关闭，需要明确打开。

Camelot 基础规则参考 [Mixed In Key 官方说明](https://mixedinkey.com/camelot-wheel/)。分数不包含实际音频、乐句、响度、人声重叠或现场效果，不能保证过渡质量。

总计划时长 = 已知播放段时长合计 − 有效重叠时长。未知时长单独列出，不伪装成完整 Set；重叠不能超过相邻任一播放段，也不能使中间曲目的两个过渡重叠越界。移动 / 删除曲目会清除受影响的新相邻关系的重叠和转场备注，其他备注保留。推荐仍排除已用曲目；rekordbox 歌单中重复出现的曲目允许保存并保留曲序，每个出现位置有独立条目 ID。

## 轻量练习记录

记录日期、成员、实际练习分钟、开心程度、主题与笔记，可关联 Set。近 30 天只统计用户记录的实际分钟，不用计划时长冒充播放时长。不做积分、排名、连续打卡或自动催促。

保存时留存当时的 Set 名称和曲目数；随后删除 / 修改 Set 不会把过去练习改写成新的编排。练习可单独编辑、删除。

## 保存、共享与边界

- 数据保存于家庭文档的可选 `preferences.lifestyle`；旧备份没有该字段仍可打开。使用已有本机备份、Supabase 持久化、版本冲突保护、双成员同步。
- 曲目、评分、笔记和练习对两位成员共享；不是个人私密歌单。显示本机 / 云端状态，未确认云端成功不冒充已同步。
- 趣味操作不改资产、负债、现金流或财务快照。财富顾问请求排除兴趣元数据，当前顾问也不会自动编辑曲库。
- JSON 兴趣备份包含全部兴趣字段；恢复前确认，只替换兴趣模块，不替换财富、聊天或季度复盘。完整家庭 JSON 备份也包含本模块。
- 编辑 / 导入 / 恢复捕获基线；另一页面或设备已更改时保留草稿、拒绝覆盖。家庭文档层仍有数据库版本校验。
- 首版上限 1,000 曲目、60 套 Set（每套最多 200 首）、300 条练习，拒绝超限，不自动删除旧记录。CSV ≤1MB，兴趣 JSON ≤3MB。以后扩展为大曲库时应拆分独立表与分页，而非无限塞进家庭文档。
- 不上传音频、不连接 Spotify、不获取版权受限数据，不提供实际混音 / 播放器。仅从用户有权使用的本地 / 合法导出元数据开始。

`tests/lifestyle.test.ts` 覆盖评分、调性、未知数据、Cue / 时长、CSV、备份、并发保护和不改财富。`tests/e2e/lifestyle.spec.ts` 覆盖完整交互、刷新、导入与撤销、手机布局、共享和顾问请求隔离。`tests/lifestyle.sql` 在临时家庭事务内验证真实数据库共享、RLS 隔离、版本冲突和兴趣 / 财富并存，结束全部回滚。
